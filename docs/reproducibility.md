# Reproducibility and evidence

## Replay generation

`replay/corpus/transactions.json` names the exact seven transaction cases and caller aliases. The generator compiles checked-in Solidity sources with pinned `solc` 0.8.30 and optimizer settings, deploys baseline/candidate contracts to fresh local Hardhat state, executes each case in order, and captures real deployment and transaction receipts. The local chain ID is 31337 and its clock is fixed from the corpus epoch so repeated runs remain stable.

Run:

```powershell
npm run replay:generate
npm run replay:verify
npm run test:replay
```

The generator writes four replay scenarios, their CI receipt JSON, human-readable HTML evidence, source/corpus provenance, and public copies. `replay/schemas/` defines the machine-readable report and CI receipt shapes. The tests validate schemas, content hashes, receipt status fields, expected differences, synthetic-data disclosure, and public-copy equality.

`npm run replay:verify` regenerates the bundles and checks that the evidence output matches current sources and corpus. It intentionally does not describe a hosted GitHub Actions run as independent CI. A deployment should pin the exact generated report and CI receipt bytes in its declaration; after changing replay code or corpus, regenerate, re-prepare the declarations, and republish.

## Test artifact isolation and proof recovery

GenLayer test-runner output is directed to `test-artifacts/` through `gltest.config.yaml`, keeping it separate from deployment receipts and proof manifests under `artifacts/` and `deploy/`. Active deployment, integration, and proof scripts accept `RATCHET_NETWORK=studionet` only. Recovery fetches only Studionet's recorded transactions and does not submit transactions or change contract state.

## Contract validation

`npm run contract:lint` runs the GenVM linter against the contract's stable runner. `npm run contract:schema` writes `deploy/ratchet.abi.json` from the contract. `npm run test:direct` executes direct-mode contract tests against the runner hash pinned in the contract header. The Windows stdin compatibility shim is under `tests/direct/` and affects the local direct runner only; it does not alter the deployed contract.

## Deployment proof

Stable Studionet manifests and receipts are generated by the deployment and seed scripts. Proof verification checks saved finalized transaction receipts, live transactions and contract reads, adjudication receipts, current public artifact bytes, and committed hashes on chain `61999`. `npm run test:integration` separately checks release state and bond accounting alongside successful execution and consensus metadata.

## What the artifacts do not establish

These bundles show that a specific local EVM corpus executed against the checked-in examples. They do not constitute exhaustive coverage, an audit, a production deployment, a formal verification result, or proof that a different protocol is secure. GitHub Actions publishes a commit-bound replay hash-check artifact; it is reproducibility evidence and not an independent security audit. `deploy/studionet-proof.json` records actual public-demo writes; without a current verified chain proof, only local replay evidence exists.
